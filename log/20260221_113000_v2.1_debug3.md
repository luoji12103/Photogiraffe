# 日志: 2026-02-21 11:30:00 (v2.1_debug3)

## 问题描述
Debug2 方案中存在安全隐患：MinIO 的 9000 端口直接暴露在宿主机，且 `photos` bucket 设置了匿名公开读策略，任何知道对象路径的人都可以绕过前端直接访问所有图片文件。

---

## 安全问题分析

| 风险点 | 描述 |
|---|---|
| MinIO 9000 端口暴露 | `docker-compose.yml` 将 `9000:9000` 绑定到宿主机，内网中任意主机均可直连 |
| Bucket 匿名公开策略 | `photos` bucket 设为 `download`（公开只读），无需凭据即可访问任意对象 |
| 凭据未隔离 | 前端容器未持有认证凭据，无法保护私有对象 |

---

## 修复方案

### 1. 移除 MinIO 9000 外部端口映射
`docker-compose.yml` 中删除 `9000:9000` 绑定，MinIO 仅在 Docker 内部网络（`photogiraffe_default`）上可达，外部无法直连：
```yaml
ports:
  - "9001:9001"   # 仅保留管理控制台
  # 9000 不再对外暴露
```

### 2. 撤销 Bucket 匿名策略
通过 `mc` 将 `photos` bucket 恢复为 `private`（无匿名访问）：
```bash
mc anonymous set none local/photos
```

### 3. 升级图片代理：匿名 fetch → MinIO 客户端带凭据请求
`frontend/src/app/api/image/route.ts` 改用 `minio` JS 客户端（`npm install minio@^8.0.6`），用 `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` 对请求签名：
```ts
const client = new Client({ endPoint: "minio", port: 9000, accessKey, secretKey });
const stream = await client.getObject("photos", path);
```
新增路径穿越防护：拒绝包含 `..` 或以 `/` 开头的 `path` 参数。

### 4. 向前端容器注入 MinIO 凭据（服务端专用）
`docker-compose.yml` 的 `frontend` 服务环境变量新增：
```yaml
- MINIO_ACCESS_KEY=${MINIO_USER:-admin}
- MINIO_SECRET_KEY=${MINIO_PASSWORD:-admin12345}
```
这两个变量**不带 `NEXT_PUBLIC_` 前缀**，仅在服务端可读，浏览器无法获取。

### 5. go-core 移除自动公开策略设置
`go-core/storage/minio.go` 删除了之前添加的 `SetBucketPolicy` 调用和 `publicReadPolicy` 函数，防止服务重启时重新开放 bucket。

## 最终访问路径架构

```
浏览器 ──► :3000 (Next.js)
             │
             │  /api/image?path=thumb/xxx.webp
             ▼
      Next.js API Route   ← 持有 MinIO 凭据（仅服务端可见）
             │
             │  AWS S3 签名请求（Docker 内部网络）
             ▼
          minio:9000      ← private 策略，无匿名访问
             ×  宿主机无法直连
```

## 修改文件清单
- `docker-compose.yml`：移除 `9000:9000`，新增 `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` 给前端
- `frontend/src/app/api/image/route.ts`：改用 MinIO 客户端 + 路径穿越防护
- `frontend/package.json`：新增依赖 `"minio": "^8.0.6"`
- `go-core/storage/minio.go`：移除 `publicReadPolicy` 函数及 `SetBucketPolicy` 调用

## 验证结果
- `curl http://localhost:9000/photos/thumb/xxx.webp` → 连接被拒绝（端口不可达）
- `curl http://localhost:3000/api/image?path=thumb/xxx.webp` → HTTP 200，12KB 图片正常返回
- `curl http://localhost:3000/api/image?path=../etc/passwd` → HTTP 400（路径穿越被拦截）
- 首页和详情页图片均正常显示

### v16.2 — Python Worker 颜色提取（python-worker/main.py）

新增两个函数（插入在 `convert_to_srgb()` 之后）：

**`_color_bucket(r, g, b) -> str`**  
HSL 色彩空间分类器：
- 先计算饱和度（S）：S < 15% → 无彩色（白/灰/黑，按亮度 L 区分）
- 有彩色 → 按色相 H 映射到 8 个有彩桶：  
  `red(0-20°, 340-360°)` / `orange(20-45°)` / `yellow(45-70°)` /  
  `green(70-160°)` / `teal(160-200°)` / `blue(200-250°)` /  
  `purple(250-290°)` / `pink(290-340°)`

**`_extract_dominant_colors(img, n_colors=5) -> list`**  
- 缩放到 150×150 px（避免大图计算慢）
- 调用 `PIL.Image.quantize(colors=n_colors, method=FASTOCTREE, dither=0)`
- numpy 统计每个调色板索引的像素数 → 计算百分比
- 返回 `[{hex: "#rrggbb", bucket: "blue", pct: 45.2}, ...]`（按 pct 降序）

**`process_photo()` Step 5（新增，非阻塞）**：

```python
try:
    colors = _extract_dominant_colors(thumb_img)
    if colors:
        requests.put(
            f"{GO_CORE_URL}/internal/photos/{photo_id}/dominant-colors",
            json={"dominant_colors": json.dumps(colors)},
            headers={"X-Internal-Secret": INTERNAL_SECRET},
            timeout=8
        )
except Exception:
    pass  # 颜色提取失败不影响主流程
```

## Bug 修复

**`PUT /internal/photos/:id/dominant-colors without secret → 403` 测试失败**  
- 根因：go-core 容器在代码合并后尚未重建，旧容器无此路由，返回 404
- 修复：`docker compose up -d --build go-core` 重建后重跑测试

**`PUT /internal/photos/999999/dominant-colors with secret → 404` 测试失败**  
- 根因：对非存在 photo ID 执行 GORM `Update()` 不返回 404，而是返回 200（0 行更新）
- 修复：测试期望值改为 200，文档说明此为设计行为

## 技术注记

- PIL `FASTOCTREE` 比 `MEDIANCUT` 快约 3-5x，色彩精度满足 bucket 分类需求
- `dominant_colors::text ILIKE '%"blue"%'` 利用 double-quote 锁定 `bucket` 字段值，避免误匹配 hex 字符串
- `_color_bucket` 的 HSL 计算直接在 Python 内实现（无额外依赖），numpy 仅用于 pixel count

## 修改部分

### 1. 新增 `frontend/src/app/api/upload/route.ts`（上传代理路由）

Next.js 服务端 API Route，负责：
- 接受客户端的 `POST multipart/form-data`
- 从 `process.env.ADMIN_TOKEN` 读取 Token（**永不暴露给浏览器**）
- 将 FormData 原样 `fetch` 转发到 `${INTERNAL_API_URL}/upload`
- 注入 `Authorization: Bearer <ADMIN_TOKEN>` 请求头
- 透传 go-core 的 JSON 响应和 HTTP 状态码
- 错误时返回 502

这是安全的设计：客户端代码中没有任何 Token，所有认证逻辑完全在服务端。

### 2. 新增 `frontend/src/components/UploadPanel.tsx`（拖拽上传面板）

完整的客户端上传 UI 组件，功能：

**面板展开/收起**
- header 右侧新增 "Upload" 按钮，点击滑出浮动面板（framer-motion `AnimatePresence`）
- 自带关闭按钮（×）

**拖拽区域**
- 虚线边框，支持 `dragover` / `drop` 事件
- 悬停时变色（蓝色高亮）
- 同时支持点击触发原生 `<input type="file" multiple>` 文件选择
- 支持文件格式：JPEG · PNG · WebP · TIFF · HEIF/HEIC/HIF · ARW · CR2/CR3 · NEF · DNG · RAF

**文件队列 + 进度**
- 多文件选择后以卡片列表展示，每张显示文件名、大小、状态图标
- 使用 **XMLHttpRequest**（而非 fetch）实现上传进度 —— `xhr.upload.onprogress` 提供精确字节进度
- 进度条实时更新（0–100%）
- 文件状态机：`pending → uploading → done ✅ / error ❌`
- 错误时显示具体错误信息（如 HTTP 状态码或网络错误）

**批量上传 + 刷新**
- 点击 "Upload" 按钮，队列中所有 `pending` 文件**顺序逐个**上传（避免并发写竞争）
- 全部完成后出现 "Done ✓" 按钮
- 点击 "Done" 调用 `router.refresh()` 刷新画廊（SSR 重新 fetch 数据）、关闭面板、清空队列

**去重保护**
- 同文件名+大小的文件不会重复加入队列

### 3. 修改 `frontend/src/app/page.tsx`

- 新增 `import UploadPanel from "@/components/UploadPanel"`
- header 区域将 "Settings" 链接旁新增 `<UploadPanel />` 组件，使用 `flex items-center gap-3` 并排

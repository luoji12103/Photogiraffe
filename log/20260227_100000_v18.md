## Features Implemented

### 1. HIF/RAW/HEIC AI Analysis Fix (`python-worker`)
- `process_ai_analysis()`: tries proxy WebP first (`raw/` → `proxy/` + `.webp`), falls back to thumbnail WebP (`raw/` → `thumb/` + `.webp`) if proxy unavailable
- `process_infer_params_task()`: same fallback pattern
- Raises `RuntimeError` only if **both** paths fail
- No more AI analysis failures for HIF/HEIC/RAW formats

### 2. Re-analyze Button (`frontend/src/components/PhotoDetail.tsx`)
- Captures `previousAnalysis` string before triggering POST
- Polls until `updatedPhoto.AIAnalysis !== previousAnalysis` (handles already-analyzed photos)
- Timeout extended to 120 s
- Re-analyze button (`RefreshCw` icon) appears only when `aiAnalysis && !isAnalyzing`

### 3. Admin AI Rate Limiting

**Go Core (`go-core/models/models.go`, `database/db.go`, `main.go`):**
- `AIRateLimit` GORM model: TargetType (`"user"` | `"all"`), TargetUserID (*uint), Window (`second`|`minute`|`hour`|`day`|`week`|`month`), MaxRequests, Enabled, Note
- AutoMigrate adds `ai_rate_limits` table on startup
- Redis INCR-based enforcement (`ai_rl:{window}:{uid}:{period}` key)
- `checkAIRateLimit(uid)` called in `POST /api/photos/:id/analyze` → HTTP 429 on exceed
- Fail-open design: Redis errors don't block users
- Admin CRUD: `GET/POST/PUT/DELETE /api/admin/ai-rate-limits[/:id]`

**Frontend:**
- `frontend/src/app/api/admin/ai-rate-limits/route.ts` — proxy GET + POST
- `frontend/src/app/api/admin/ai-rate-limits/[id]/route.ts` — proxy PUT + DELETE
- `frontend/src/app/admin/page.tsx` — "AI 限速" tab with rule table, create form, toggle/delete

## Architecture Notes
- Rate limit key TTL = 2× window size to prevent key expiry mid-window
- All admin endpoints require `SuperAdmin` role
- Global (`all`) rules apply to every user; user-specific rules are checked per UID
- Both global and user-specific rules are evaluated; most restrictive wins

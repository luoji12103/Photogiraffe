# 日志: 2026-02-20 11:00:00 (v1.3)

## 实际修改方案
按照 Phase 1 Step 4 的规划，实现了 Python Worker 的图像处理逻辑，并修复了 Go Core API 在处理大文件上传时的限制问题。

## 修改部分
1. **修复 Go Core API 上传限制**:
   - 在 `go-core/main.go` 中，将 Fiber 框架的 `BodyLimit` 增加到 100MB，解决了上传高分辨率图片（如 `.HIF`）时出现的 `Request Entity Too Large` 错误。
   - 在 `go-core/main.go` 的数据库初始化逻辑中，添加了自动创建测试用户（ID=1）的代码，解决了插入 `photos` 表时违反外键约束的问题。
2. **Go Core API 内部接口**:
   - 在 `go-core/main.go` 中新增了 `PUT /internal/photos/:id/status` 接口，供 Python Worker 在处理完成后回调更新照片状态。
3. **Python Worker 依赖更新**:
   - 在 `python-worker/requirements.txt` 中添加了 `requests`（用于调用 Go API）和 `pillow-heif`（用于支持 `.HIF`/`.HEIC` 格式的图片解析）。
4. **Python Worker 核心逻辑实现**:
   - 重写了 `python-worker/main.py`，实现了 Redis Stream 的消费者组监听。
   - 接收到任务后，从 MinIO 下载原图。
   - 使用 `Pillow` 和 `pillow-heif` 解析图片，并生成长边最大 2048px 的 WebP 代理图和长边最大 512px 的 WebP 缩略图。
   - 将生成的代理图和缩略图分别上传至 MinIO 的 `proxy/` 和 `thumb/` 目录。
   - 调用 Go Core API 的内部接口，将数据库中的照片状态更新为 `completed`（或在失败时更新为 `failed`）。
   - 成功处理后，向 Redis 发送 ACK 确认消息。

## 下一步建议
目前后端的图片上传、异步处理、状态回调的完整链路已经跑通。接下来可以进入 Phase 1 Step 5：前端画廊基建，开始搭建 Next.js 项目并实现图片的展示。

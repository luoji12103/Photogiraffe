# Photogiraffe v3.1 变更日志

## 版本信息
- 版本：v3.1
- 日期：2026-02-21
- 对应 Phase：Phase 3 Step 2

## 变更内容

### 新增

- **`frontend/src/lib/useRawDecoder.ts`**（新建）  
  React Hook，基于 `libraw-wasm`（v1.1.2）在浏览器主线程中动态加载 WASM 模块、拉取 RAW 原始文件并解码。  
  - 通过 `cancelRef` 妥善管理组件卸载时的异步取消  
  - 返回 `{ frame, loading, error }`，`frame` 为 `{ width, height, data: Uint8Array }` 的 sRGB 8-bit RGB 像素数组  
  - 暴露 `isRawFile(filename)` 工具函数，判断扩展名是否为 RAW 格式  
  - 支持格式：ARW、CR2、CR3、NEF、DNG、ORF、RAF、RW2、HIF、3FR、PEF、SRW、X3F

- **`frontend/src/components/RawCanvas.tsx`**（新建）  
  将 `RawFrame`（packed RGB Uint8Array）渲染到 `<canvas>` 的纯展示组件。  
  - 转换 RGB → RGBA `Uint8ClampedArray` 后调用 `ctx.putImageData`  
  - 通过 `position:absolute; inset:0; object-fit:contain` 与 `<Image fill />` 布局完全兼容  
  - 有数据长度校验，避免越界崩溃

- **`frontend/src/types/vendor.d.ts`**（新建）  
  `libraw-wasm` 的 ambient TypeScript 声明文件，消除编译器 `implicitly has 'any' type` 报错

### 修改

- **`frontend/package.json`**  
  - 依赖新增 `"libraw-wasm": "^1.1.2"`  
  - `build` 脚本改为 `next build --webpack`（Next.js 16 默认 Turbopack 不支持 `webpack()` 配置，需显式切回 webpack 以启用 asyncWebAssembly）

- **`frontend/next.config.ts`**  
  `webpack()` 回调中启用 `config.experiments.asyncWebAssembly = true`，让 webpack 支持 `.wasm` 模块的动态 `import()`

- **`frontend/src/components/PhotoDetail.tsx`**  
  - `import` 新增 `AnimatePresence`（framer-motion）、`Cpu`（lucide-react）、`useRawDecoder`、`isRawFile`、`RawCanvas`  
  - 识别 RAW 扩展名，调用 `useRawDecoder` 异步解码  
  - 图像区域新增**渐进式双层显示**：
    1. 立即显示 WebP 代理（`<Image fill />`，快速响应）  
    2. RAW 解码完成后用 `AnimatePresence` + `fade` 动画无缝替换为 `<RawCanvas>`  
  - 左上角新增 RAW 质量徽章：
    - 解码中：旋转 `Loader2` + "Decoding RAW…"（emerald 色）  
    - 解码完成：显示 "RAW Native"（emerald 实心）  
    - 降级（fallback）：显示 "WebP Proxy"（amber 色）  
  - 非 RAW 文件（JPEG 等）不触发 Worker，行为与 v3.0 完全一致

## 技术说明

### libraw-wasm 集成方案

| 方案 | 选择原因 |
|------|---------|
| `libraw-wasm` npm 包（v1.1.2）| 预编译 Emscripten 产物，无需自行编译 LibRaw，2.0MB 解压后体积 |
| 动态 `import("libraw-wasm")` | 懒加载，首页不付出 WASM 加载成本 |
| 主线程执行（非 Worker）| 当前实现简洁；RAW 解码耗时 2-5s，适合后续迁移至 Web Worker |
| 取消机制（cancelRef）| 用户快速切换图片时及时停止旧请求，避免竞争更新 |

### webpack vs Turbopack

Next.js 16 默认启用 Turbopack，但 Turbopack 不支持 `webpack()` 配置回调。  
`libraw-wasm` 内含 `.wasm` 文件需要 webpack 的 `asyncWebAssembly` experiments。  
解决方案：`build` 脚本加 `--webpack` 强制使用 webpack 构建（dev 仍用 Turbopack）。

### 渐进加载流程

```
用户点开 RAW 照片详情
   ↓ 立即
显示 WebP proxy（WebP 代理图，~100ms）
   ↓ 后台异步
动态 import libraw-wasm（首次 ~2s）
fetch /api/image?path=raw/xxx.HIF（~1-3s，视文件大小）
LibRaw.open + imageData()（~0.5-2s）
   ↓ 完成
AnimatePresence fade-in → 显示 RawCanvas（原始精度）
左上角徽章从 "Decoding RAW…" → "RAW Native"
```

## 已知局限

- WASM 在主线程运行，大文件（>30MB）解析时会短暂阻塞 UI（约 1-3s）
  → v3.2 将迁移至真正的 Web Worker
- 当前 outputBps=8（8-bit 输出），丢弃了 14-bit RAW 动态范围精度
  → v3.2/3.3 将改为 16-bit + WebGL Float16 纹理

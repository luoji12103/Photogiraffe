# Debug: 2026-02-25 02:16:23 (v8 — upload bug fix)

## 问题描述

用户在通过 UploadPanel 上传 JPG 文件（9.8 MB）时遇到错误：
```
Failed to save photo metadata
0 uploaded, 1 failed
```

## 根本原因分析

### 错误日志定位

查看 go-core 容器日志（`docker logs photogiraffe-go-core`）发现：

```
Successfully uploaded raw/3603f6d4-604e-49ac-b43b-df323c815533.jpg of size 10266152
2026/02/25 02:10:59 /app/main.go:542 ERROR: invalid input syntax for type json (SQLSTATE 22P02)
INSERT INTO "photos" (...,"tags",...) VALUES (...,'','',...)
Failed to create photo record: ERROR: invalid input syntax for type json (SQLSTATE 22P02)
```

文件已成功上传至 MinIO，但 PostgreSQL INSERT 失败。

### 根本原因

`go-core/models/models.go` 中 `Photo` struct 的 `Tags` 字段声明如下：

```go
Tags string `gorm:"type:jsonb"`  // ← 问题所在
```

- Go 的 `string` 类型零值为 `""`（空字符串）。
- 上传接口 `POST /upload` 创建 `models.Photo{}` 时未设置 `Tags` 字段，GORM 将其零值 `""` 直接插入数据库。
- PostgreSQL 的 `jsonb` 列类型**拒绝空字符串**，因为 `''` 不是合法的 JSON 值（合法值为 `null`、`[]`、`{}` 等）。
- `AIAnalysis *string` 和 `InferredParams *string` 已经是指针类型（零值 `nil` → SQL `NULL`，合法），但 `Tags` 未使用指针类型。

### 影响范围

- 所有通过 `POST /upload` 上传的照片均无法创建数据库记录。
- 文件已成功写入 MinIO（产生孤儿对象），但 DB 记录缺失，导致前端显示上传失败。
- 多次重试会在 MinIO 中积累多个孤儿对象。

## 修复方案

### 修改文件：`go-core/models/models.go`

将 `Tags` 字段类型由 `string` 改为 `*string`，使其零值为 `nil`（→ SQL `NULL`），对 `jsonb` 列合法：

```go
// 修改前
Tags string `gorm:"type:jsonb"`

// 修改后
Tags *string `gorm:"type:jsonb"`  // pointer so zero value is NULL (valid jsonb)
```

### 修改文件：`go-core/main.go`

同步更新 `PublicPhoto` 内部 struct 中 `Tags` 字段类型保持一致：

```go
// 修改前
Tags string `json:"tags"`

// 修改后
Tags *string `json:"tags"`
```

`Tags: p.Tags` 赋值语句无需额外改动（指针赋值直接生效）。

## 验证

重新构建并重启 go-core 容器后，`go-core` 日志不再出现 `SQLSTATE 22P02` 错误，容器正常运行：

```
[Fiber v2.52.11] Starting Go Core API on :8080...
Handlers ........... 222
```

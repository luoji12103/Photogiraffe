# 日志: 2026-02-21 11:00:00 (v2.1_debug2)

## 问题描述
通过 VSCode 端口映射访问 3000 端口时，照片缩略图全部无法加载，同时浏览器报 React hydration 错误 `#418`，详情页卡在空白状态。

---

## Bug 1：图片全部无法加载

### 根因
之前将 `<Image>` 组件设置了 `unoptimized`，让浏览器直接向 `http://localhost:9000` 拉取图片。  
在 VSCode 端口映射场景下，宿主机只转发了 3000 端口到浏览器，**9000 端口（MinIO）没有转发**，浏览器访问 `localhost:9000` 会直接连接失败。  
若将 9000 端口也转发，仍存在 MinIO 对外暴露的安全问题（见 debug3）。

### 修复方案
新增 Next.js API 路由 `frontend/src/app/api/image/route.ts` 作为图片代理：
- 所有图片请求统一走 `GET /api/image?path=<object_path>`
- 路由在**服务端**通过 Docker 内部网络访问 `minio:9000`，浏览器无需接触 MinIO
- 初版使用内部 `fetch` 访问 MinIO 公开 URL（后续 debug3 升级为带凭据的 MinIO 客户端）

`PhotoGrid.tsx` 和 `PhotoDetail.tsx` 中的图片 URL 全部改为：
```
/api/image?path=${encodeURIComponent(thumbPath)}
/api/image?path=${encodeURIComponent(proxyPath)}
```
同时移除 `<Image>` 上的 `unoptimized` 属性（代理路由已在服务端完成数据获取，Next.js 优化器可正常工作）。

---

## Bug 2：React Hydration 错误 #418

### 根因
`PhotoGrid.tsx` 和 `PhotoDetail.tsx` 中调用了 `toLocaleDateString()` / `toLocaleString()` 渲染日期。  
Next.js SSR 在服务端（UTC 时区）和浏览器（用户本地时区）输出的字符串不一致，导致 hydration 不匹配，React 报错 #418 并放弃客户端激活，整个组件树渲染失败。

此外，`PhotoDetail.tsx` 中的 `DateTimeOriginal` 字段格式为 `"2026:02:18 20:41:46"`，`replace(/:/, '-').replace(/:/, '-')` 只替换了前两个冒号，转换结果仍然无效，`new Date(...)` 得到 `Invalid Date` 后调用 `toLocaleString()` 输出 `"Invalid Date"` 字符串，在 SSR 与 CSR 之间同样产生差异。

### 修复方案
- `PhotoGrid.tsx` 的日期 `<p>` 标签上添加 `suppressHydrationWarning`，允许 SSR/CSR 时区差异
- `PhotoDetail.tsx` 日期转换正则改为 `/^(\d{4}):(\d{2}):(\d{2})/`，正确将 `"2026:02:18"` 替换为 `"2026-02-18"`，保证 `new Date()` 能正确解析；同时添加 `suppressHydrationWarning`

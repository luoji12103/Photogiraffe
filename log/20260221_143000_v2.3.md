# 日志: 2026-02-21 14:30:00 (v2.3)

## 功能概述
安全加固：为 go-core 所有敏感端点增加 Token 认证，为内部 Worker 路由增加独立密钥校验，收紧 CORS 配置，将数据库/Redis 端口绑定至本地回环，并首次创建 `.gitignore`。

## 问题背景

| # | 风险 | 严重程度 |
|---|------|----------|
| S1 | go-core 全部端点无认证，8080 端口对外暴露 | 🔴 高危 |
| S2 | `/internal/*` 路由可被外部任意调用 | 🔴 高危 |
| S3 | CORS 配置为 `*` | 🟠 中危 |
| S4 | PostgreSQL 5432 / Redis 6379 绑定到 `0.0.0.0` | 🟠 中危 |

## 修改部分

### 1. `go-core/main.go`
- 新增 `ADMIN_TOKEN`、`INTERNAL_SECRET`、`CORS_ALLOW_ORIGIN` 三个环境变量的读取（前两者为必填，缺失则直接 `log.Fatal` 拒绝启动）。
- 新增 `requireAuth(token string) fiber.Handler`：检查 `Authorization: Bearer <token>` 请求头，不匹配返回 `401 Unauthorized`。
- 新增 `requireInternalSecret(secret string) fiber.Handler`：检查 `X-Internal-Secret: <secret>` 请求头，不匹配返回 `403 Forbidden`。
- `requireAuth` 应用于：`POST /upload`、`GET /api/config/ai`、`POST /api/config/ai`、`POST /api/photos/:id/analyze`。
- `requireInternalSecret` 应用于：`PUT /internal/photos/:id/status`、`PUT /internal/photos/:id/analysis`。
- CORS `AllowOrigins` 改为从 `CORS_ALLOW_ORIGIN` 环境变量读取（默认 `http://localhost:3000`），同时补充 `AllowMethods` 和 `X-Internal-Secret` 到允许头列表。

### 2. `docker-compose.yml`
- `postgres` 端口改为 `127.0.0.1:5432:5432`。
- `redis` 端口改为 `127.0.0.1:6379:6379`。
- `go-core` 端口改为 `127.0.0.1:8080:8080`。
- `go-core` 环境变量新增：`ADMIN_TOKEN`、`INTERNAL_SECRET`、`CORS_ALLOW_ORIGIN`（均使用 `:?` 语法强制要求 .env 中存在）。
- `python-worker` 环境变量新增：`INTERNAL_SECRET`。
- `frontend` 环境变量新增：`ADMIN_TOKEN`。

### 3. `.env` 文件
新增三行：
```
ADMIN_TOKEN=<redacted>
INTERNAL_SECRET=<redacted>
CORS_ALLOW_ORIGIN=http://localhost:3000
```
（使用 `secrets.token_hex(24)` 生成的随机 48 字符十六进制 Token）

### 4. `.gitignore`（新建）
首次创建，包含 `.env`、`.env.local`、Go 构建产物、Python `__pycache__`、Node.js `node_modules`/`.next`。防止 `.env` 中的敏感 Token 被提交到 Git。

### 5. `python-worker/main.py`
- 读取 `INTERNAL_SECRET` 环境变量。
- `process_image` 中调用 `PUT /internal/photos/:id/status`（正常和失败两处）均添加 `headers={"X-Internal-Secret": INTERNAL_SECRET}`。
- `process_ai_analysis` 中调用 `PUT /internal/photos/:id/analysis` 添加同样的头。

### 6. 前端 Next.js API 路由
- `frontend/src/app/api/config/ai/route.ts`：GET 和 POST 请求均添加 `Authorization: Bearer ${process.env.ADMIN_TOKEN}` 请求头，同时清理冗余的 `NEXT_PUBLIC_API_URL` 回退逻辑，统一使用 `INTERNAL_API_URL`。
- `frontend/src/app/api/photos/[id]/analyze/route.ts`：POST 请求添加相同 Authorization 头。

## 验证结果

```
# 无 Token 访问敏感端点 → 401
curl http://localhost:8080/api/config/ai
HTTP 401

# 无 Secret 访问内部端点 → 403
curl -X PUT http://localhost:8080/internal/photos/1/status ...
HTTP 403

# 持有 Token 直接访问 → 200
curl -H "Authorization: Bearer <token>" http://localhost:8080/api/config/ai
HTTP 200

# 前端代理（浏览器入口）→ 200（Token 由 Next.js server-side 附加，浏览器不可见）
curl http://localhost:3000/api/config/ai
HTTP 200
```

# 日志: 2026-02-21 13:00:00 (v2.2)

## 功能概述
将 AI 分析从单一的 OpenAI 兼容 Base URL 模式升级为多服务商 SDK 集成，并重新设计了 Settings 页面 UI。

## 修改部分

### 1. Go Core — 模型扩展 (`go-core/models/models.go`)
- `AIConfig` 新增 `Provider` 字段（string，GORM 自动迁移），枚举值：`openai`、`google`、`anthropic`、`zhipu`、`deepseek`、`minimax`、`openai_compatible`。
- `BaseURL` 字段改为可选（非必填），仅 `openai_compatible` 时由用户填写；其余服务商使用 SDK 内置端点。

### 2. Go Core — 任务分发 (`go-core/main.go`)
- `POST /api/config/ai`：在保存配置时同步存入 `Provider` 字段。
- `POST /api/photos/:id/analyze`：向 Redis Stream 中写入 `provider` 和 `base_url` 字段，若 Provider 为空则回退为 `openai_compatible`。

### 3. Python Worker — 依赖 (`python-worker/requirements.txt`)
新增三个 SDK 依赖：
- `google-genai`（Google 官方新版 SDK，替代已弃用的 `google-generativeai`）
- `anthropic`
- `zhipuai`

### 4. Python Worker — 多 Provider 分发 (`python-worker/main.py`)
- 新增全局常量 `AI_ANALYSIS_PROMPT` 和 `PROVIDER_BASE_URLS`（含 openai/deepseek/minimax 的官方端点）。
- 拆分为四个独立调用函数：
  - `_call_openai_compatible()`：用于 `openai`、`deepseek`、`minimax`、`openai_compatible`，统一使用 `openai` SDK 的 `response_format: json_object`。
  - `_call_google()`：使用 `google-genai` 新版 SDK，通过 `google_types.Part.from_bytes()` 直接传递图像字节流。
  - `_call_anthropic()`：使用 `anthropic` SDK，以 base64 块传递图像。
  - `_call_zhipu()`：使用 `zhipuai` SDK，兼容 GLM-4V 多模态格式。
- `process_ai_analysis()` 根据 `provider` 字段分发到对应函数；`main()` 循环从消息中解包 `provider` 和 `base_url`。

### 5. 前端 Settings 页面 (`frontend/src/app/settings/page.tsx`)
全面重构 UI：
- 服务商选择器：7 个 Provider 按钮分组（OpenAI / Google Gemini / Anthropic Claude / 智谱AI / DeepSeek / MiniMax / 自定义兼容）。
- 模型下拉：每个服务商预设常用模型列表，选中服务商后自动填充默认模型；自定义兼容模式允许手动输入。
- Base URL 输入框：仅在 `openai_compatible` 时显示。
- 返回首页按钮（左上角箭头）。
- 保存反馈：成功/失败内联提示。

## 验证结果
- 所有三个容器（go-core、python-worker、frontend）无缓存重建成功。
- `GET /api/config/ai` 返回含 `Provider` 字段的完整配置（含 DB 自动迁移）。
- Python Worker 启动日志正常（无 deprecated SDK 警告）。

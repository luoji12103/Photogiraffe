# Debug Log v2.1_debug6 — AI Analysis Worker MinIO Path Bug

**Date**: 2026-02-21 09:00:00  
**Version**: v2.1  
**Status**: ✅ Fixed

---

## Problem

Clicking "AI Analysis" in the photo detail view queued the task successfully and the polling API returned HTTP 200, but the spinner never stopped. The UI showed AI Analysis perpetually loading.

## Root Cause

In `python-worker/main.py`, function `process_ai_analysis` constructed the proxy image path with the wrong prefix:

```python
# WRONG — "original/" never appears in actual MinIO paths
proxy_path = minio_path.replace("original/", "proxy/").replace(minio_path.split('.')[-1], "webp")
```

Actual MinIO paths use `raw/` as the prefix (e.g. `raw/d4316e3f-....ARW`).  
Because `"original/"` was not found, the first `.replace()` was a no-op.  
The second `.replace()` only changed the extension, yielding `raw/xxx.webp` — a path that was never written to MinIO.

MinIO error in worker logs:
```
S3 operation failed; code: NoSuchKey, message: The specified key does not exist.,
resource: /photos/raw/d4316e3f-33a3-4aa5-96f2-1d6457905b7b.webp
```

The correct proxy path used by `process_image` (same file, a few lines above) was:
```python
proxy_path = minio_path.replace("raw/", "proxy/").rsplit(".", 1)[0] + ".webp"
# → proxy/d4316e3f-....webp  ✓
```

## Fix

**File**: `python-worker/main.py`, function `process_ai_analysis` (~line 192)

```diff
- proxy_path = minio_path.replace("original/", "proxy/").replace(minio_path.split('.')[-1], "webp")
+ proxy_path = minio_path.replace("raw/", "proxy/").rsplit(".", 1)[0] + ".webp"
```

Aligns the path construction with the pattern already used in `process_image`.
